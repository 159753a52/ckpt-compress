# A30 长程实验（2026-11-21 起）

在实验室 AIStation 的三张 A30（a30-1/2/3，即 30758、30838、30194）上运行，代码在 `experiments/scripts/a30_long/`，实验室上的根目录为 `/lihongliang/fangzl/dacp-a30/`。本目录由笔记本上的守护脚本定期从实验室拷回，不含模型状态（`.pt`）。

## 主线：ExCP 协议（2026-11-22 起，任务名 `AC_*`、`BC_*`）

按 ExCP 原文（Li et al., ICML 2024）的做法：每 N 步写一个检查点，其残差相对**上一个重建检查点**计算（链式参考，前一次删掉的误差会进入下一次残差），训练在未压缩权重上继续；每 5N 步才从重建检查点恢复一次训练。AdamW 状态无损保留。

- 研究 A：Pythia-410M / 完整 Alpaca，6000 步，N=200（恢复点 1000…5000），其余设置同下文研究 A。
- 研究 B：160M / FineWeb-Edu，7500 步，N=250（恢复点 1250…6250），其余设置同下文研究 B。
- 删除率：每个检查点两种规则删掉同样多的项。取值为 ExCP 官方阈值在其上限 `2.5 × median(|d|)` 时的删除率（在研究 A 上实测 0.905–0.917，取 0.91；研究 B 上实测 0.88）。官方默认 α=5e-5 在小 batch 微调中远达不到上限（只删 16–27%），在 160M 预训练中删 75%，故按上限取值以对应 ExCP 原文的极限压缩区间。ExCP 规则保留官方阈值的形状：逐张量 `c × median(|d|)`，c 由删除率统一确定（等价于按 `|d| / 该张量 median(|d|)` 全局排序）。
- 每个检查点都记录重建模型的损失（假如在此恢复的损伤）和实际删除率。
- 噪声对照（`AC_s42_noise`）：每个检查点只随机删 0.1% 的残差，重建几乎无损，其余流程与压缩轨迹相同；它与不压缩轨迹的差距衡量恢复本身引起的训练轨迹偏移（研究 A 用确定性内核，恢复前各轨迹逐位相同）。
- 研究 B 恢复彩排（`BK/*`，判定 `BK_decide/decision.json`）：从不压缩轨迹第 3500 步的状态出发（`BK_states/`），压缩下一个区间的残差，在第 3750 步从重建恢复，再训练 200 步，确定性内核。变体为 ExCP 规则、0.1% 随机删除、DACP-G κ=1/4/16，κ=1 并保护幅值最大的 6% 残差项（`--protect-top 0.06`），以及论文附录的 DACP-G_ρ（κ=1，ρ=4/16，`--rho`：分数外加各项自身曲率的各向同性近似 ρ·γ·d²，γ 取本阶段存活项上其余分数项均值与 d² 均值之比；彩排开始前加入，小模型冒烟测试中同删除数下保留的残差 L2 由 0.49 升到 0.55–0.65）。事先写定的规则：取恢复后 10/25/50/100/200 步平均差距最小的 DACP-G 变体，以它重跑研究 B（`BC_s42_dacpt`、`BO_s42_dacpt`）。
- 研究 B 官方默认阈值对照（`BO_*`）：ExCP 按官方代码 α=5e-5 的阈值逐存档点自行决定删多少（学习率大时删得少），DACP-G 在同一步删掉与 ExCP 运行完全相同的项数（`--count-from`，存储对等），不压缩基线复用 `BC_s42_nocomp`。
- 作废记录：先按“DACP-G 对齐官方删除数”跑过一版，因两条轨迹的残差不同，DACP-G 实际少删 1–2 个百分点，存储不对等，已停并移到实验室 `invalid/chain_matchcount_20261122/`。

下文“固定参考”的研究 A、B 是此前的旧协议，结果保留作参考。

## 旧协议：固定参考（2026-11-21，任务名 `A_*`、`B_*`）

**研究 A：长程微调，参考为固定的预训练模型。**
- Pythia-410M 从预训练权重开始在完整 Alpaca（52,002 条，1,000 条作验证集，划分与 `experiments/lib/data.py` 相同）上微调 6,000 步，batch 16（4×4 累积），seq 512，AdamW，学习率 1e-5、预热 250 步、余弦衰减到 0，权重衰减 0.01，BF16 混合精度，确定性内核。
- 故障：第 300 步起每 600 步一次，共 10 次。每次把当前权重相对预训练模型的残差按删除率 P 删除，恢复后继续训练；AdamW 状态和其余张量无损保留。
- 选择规则：ExCP 规则（保留幅值最大的残差项，全局阈值）、DACP-G（16 阶段 × 同一组 16 个评分批次，κ=1，全局精确阈值）、Inshrinkerator 规则（补充）。P ∈ {0.84, 0.95}，种子 42/43/44。

**研究 B：从头预训练，参考为周期性写出的完整检查点。**
- Pythia-160M 结构（12 层、隐藏维度 768）在 FineWeb-Edu sample-10BT 的前两个分片上从随机初始化训练 7,500 步，每步 131,072 token（batch 8×8 累积，seq 2048），共约 9.8 亿 token；学习率 6e-4、预热 75 步、余弦衰减到 6e-5，β2=0.95，权重衰减 0.1，梯度裁剪 1.0，BF16 混合精度。
- 参考：每 750 步写一次完整检查点（第 0 步为初始化）；故障在每个参考区间的中点（第 375、1125、…、7125 步，共 10 次），残差为 375 步的训练进度。
- 删除率和 κ 由彩排按预先写定的规则决定（`pilot_decide.py`）：从第 375 步（参考为初始化）和第 1125 步（参考为第 750 步）两个状态出发，比较各规则在续训 125 步后相对不压缩续训的损失差距。

## 实施过程中的调整

- 研究 A 最初按 batch 4、学习率 2e-5、2 万步启动。启动后发现三条轨迹在第一次故障之前就已明显分叉（第 1000 步验证损失 1.91 至 2.22），原因是非确定性内核加上小 batch 高学习率下的不稳定训练，轨迹间的随机差异会盖过压缩的影响。这批运行已停止并移到实验室的 `invalid/`，不参与统计；`logs/` 中对应任务的日志开头还留着这段记录（15:22–15:27 UTC）。
- 随后用两组探测确定了现在的配置：确定性内核下同一命令两次运行的验证损失逐位相同；batch 16、学习率 1e-5 时验证损失平稳下降，2e-5 时有回升。
- 研究 B 未开确定性内核（会使耗时增加约 1.7 倍）。轨迹间随机波动的大小由彩排中同一状态出发的不压缩续训与彩排预训练本身在相同步数上的差值来估计。
