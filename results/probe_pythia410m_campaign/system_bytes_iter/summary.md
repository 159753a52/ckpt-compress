# System-level bytes with iterative residual selection (Pythia-410M)

Generated by `experiments/scripts/summarize_system_bytes.py` (commands below) from the JSON files of
`experiments/scripts/run_system_bytes_comparison.py` at commit abfbd4d, CPU only
(`CUDA_VISIBLE_DEVICES=""`, 16 threads per process, 12 concurrent processes; launch scripts `iter_*.sh`).
Payload = weight residual vs the pretrained base + exp_avg + exp_avg_sq, ExCP joint moment rule (beta 2)
and ExCP 4-bit K-means quantizer for every method; restored PPL on the runner's evaluation batches,
no recovery training. Methods `*_excpq` choose the surviving residual entries of the eligible matrices
at ExCP's eligible sparsity for the same alpha (non-eligible tensors follow ExCP).

- `iterative_first_order_excpq`: stages over 0.5, 0.8, 0.9, 0.95, 0.98, 0.99, 0.995 below the target,
  then the target; |g d| with the gradient (8 scoring batches) recomputed at the partially restored point.
- `iterative_ucb_excpq`: same stages, score |mean_b c_b| + std_b(c_b)/sqrt(B), c_b = -g_b d.
- `first_order_excpq`: one-shot |g d|.
- Rows labelled `eligible_sp=... (beyond ExCP cap)`: our selection at eligible sparsity 0.95 / 0.98 / 0.99;
  ExCP's per-tensor factor is capped at 2.5, so ExCP itself stops at ~0.90 eligible sparsity and has no
  row there. Non-eligible tensors and the moment rule follow ExCP at alpha = 1e-2.

R1 (step-1000 checkpoint): the `excp_pipeline`, `dacp_excpq` and `probe_topk_m1_exact_global_excpq`
records at the 7 alphas are the existing `../system_bytes/excp_dacp*.json` runs (commit 0d39433, same
ExCP code path, CPU); the new R1 runs used `--skip-excp-record`; their recomputed ExCP masks give the same eligible
sparsity to within 6 of 3.02e8 eligible coordinates at every alpha (exact at 3 of 7 alphas; the old runs used
24 threads, the new 16). R2 (step-3000 checkpoint, workload `pythia_410m_alpaca_step3000`) was run from
scratch including `excp_pipeline` (dacp/probe not run for R2).
