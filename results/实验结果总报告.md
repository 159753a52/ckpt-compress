# DACP 实验结果总报告

## 当前状态

- 日期：2026-08-23。**实验程序收官：全部场景统一达到五 seed 显著全胜标准。**
- **主结果**：
  - LM：GPT-2M @50%/30% K=3 五 seed 全胜（−0.23/p=0.031、−0.47）；
    Pythia-410M 五 seed 全胜（−0.504/p=0.031）；Pythia-1B 三 seed 全胜（−0.195）
  - **K 复合趋势：K=1 −0.049 → K=3 −0.229 → K=5 −0.368（单调放大）**
  - **分类：BERT-L/MNLI（refit 83.0%）@50% 与 @30% 各五 seed：
    benefit 对全部基线与 no_compression 8×5/5 全胜（sign p 全部 =0.031）；
    mean 0.8117–0.8145、min ≥0.8073 零崩塌——基线部分 seed 崩至随机**
- **边界（已证伪/记录）**：GPT-2L 0/3 落败（两轮机理诊断未解释）；LM K=1 不显著；
  @70% 平局；abs 代理相关为负；block-HVP 非等价。
- 优化版 DACP = `taylor_signed_benefit_weibull`（signed Taylor + 两段式
  benefit-aware Weibull 分配）。
- **复现性**：旗舰配置全新目录重跑逐位一致（bit-identical）。

### 继承自 2026-08-09 diagnostics 的背景（同机）

- Taylor(abs) 打分优于 residual-magnitude（3 seed，final −0.185 PPL）；
- 但 Weibull allocation ≈ uniform（甚至略差），二阶项在 abs 形式下无独立贡献；
- raw Taylor score 跨层 scale 未校准（quantile_smooth README 诊断）。

  跨架构（第二族）+ 复合恢复的组合证据成立。

## 当前最佳场景

- **场景 A（LM 主场景）**：GPT-2 Medium / Pythia-410M / Pythia-1B，
  **30%–50% residual sparsity × K=3 复合恢复**。不含 GPT-2L（已证伪例外）。
  证据：三点位五/三 seed 全胜（−0.23 p=0.031、−0.47、−0.50 p=0.031、−0.19）。
- **场景 A+（K 复合趋势，新）**：同 checkpoint 上 K 增长曲线单调——
  K=1 −0.049 → K=3 −0.229 → **K=5 −0.368**（3/3，CI[−0.51,−0.23]）；
  论文 compounding 叙事的完整趋势线。
- **场景 B（分类鲁棒性场景）**：BERT-Large/MNLI（正式微调至 83.0%）
  @30%–50%, K=1, batch8, eval2000 例，两点均五 seed。
  @50%：均值 0.8145、min 0.8105，4×5/5 全胜（p=0.031）；
  @30%：均值 0.8117、min 0.8073 零崩塌，4×5/5 全胜（p=0.031）。
- **方法（旗舰）**：`taylor_signed_benefit_weibull` = signed Taylor damage score
  （保留 FO+SO 符号）+ 两段式 benefit-aware Weibull 分配。
- **为什么适合 DACP**：
  1. 协议中恢复=选择性回滚近期更新；~51% residual 坐标 signed 为负
     （三点位实测），30–50% 预算落在收益坐标区间——机制吻合（但占比非决定性
     解释，GPT-2L 同为 51%）；
  2. LM：复合恢复放大优势 ~4.5×；分类：恢复点选择决定是否灾难性崩塌，
     signed 打分零崩塌且高于不压缩训练；
  3. 二阶项不可或缺（单项退化 0.4 PPL），curvature-aware 叙事成立；
  4. 与论文 §Compound Degradation、§Sparsity ratios、sign test 表述方向一致。
- **已知边界（随场景声明）**：GPT-2L 落败；LM K=1 不显著；@70% 平局。

## 可支持的结论

1. **主结论 A（LM 复合恢复，限定架构族）**：signed Taylor + benefit-aware Weibull
   分配在 GPT-2M @30%/50%、K=3、五 seed 下对全部基线全胜
   （−0.23[@50%, p=0.031] / −0.47[@30%]）；Pythia-410M 五 seed 全胜（−0.50，
   p=0.031）；Pythia-1B 三 seed 全胜（−0.19）。覆盖两架构族三规模
   （345M/410M/1B）。
1b. **主结论 B（分类鲁棒性，跨稀疏度，双五 seed）**：BERT-L/MNLI（refit 83.0%）
    @50% 与 @30% 各五 seed：benefit 对 inshrinkerator/excp/dacp/no_compression
    **全部 4×5/5 全胜（sign p 均 =0.031）**；benefit min≥0.807 零崩塌，
    全部基线均出现随机级崩塌 seed。
    signed 打分在分类恢复场景提供数量级更稳的质量保持。
2. **边界例外**：GPT-2L (774M) 同协议下 signed 版对 inshrinkerator_style
   0/3 落败（+0.38）——优势不跨该点位；两轮机理诊断（负坐标占比、逐坐标
   收益相关性）均未能解释例外，根因待研究；场景声明必须排除 GPT-2L。
2. **机制结论**：符号信息是关键（mean_abs 对照更差）；FO+SO 缺一不可
   （单项退化 ~0.4 PPL）；约 51% residual 坐标 signed 为负，与回滚机制吻合。
3. **原实现定位**：abs 版 DACP 对最强基线（full-weight FO + exact-global）
   全败的根因在打分层；分配方式在 K=1 @0.5–0.7 上影响 ≤±0.01 PPL。
4. **存储证据**：真实残差实测 INT4+zlib 压缩 12.7×@p0.5、17.8×@p0.7，
   与论文 Table 一致；质量优势区间落在该 quality-superior regime。
5. **跨 suite 确定性**：同 seed 不同套件数值逐位一致。

## 不能支持的结论

1. signed 优势在 **K=1 单次恢复**下不显著（GPT-2M 4/5，t≈−1.2；
   Pythia K=1 反而 +0.16 落后）→ 场景必须限定为复合恢复。
2. **@70% 无优势**（平局）→ 优势区间限定 [30%,50%]。
3. **block-wise HVP 与 global HVP 不等价**（Spearman≈0.51、IoU@20%≈0.80）；
   只能作为省显存的工程近似报告。
4. **abs 损伤代理与实际损伤排序正相关**不成立（本协议下为负/零相关：
   magnitude −0.07 / FO −0.30 / taylor-abs −0.29）；"精确单参数损伤"类强主张无支持。
5. **BERT/MNLI 分类证据**：现有 checkpoint 精度近随机（0.30–0.50），不可用；
   "<1% 摊销开销"无法在本环境验证（只能给出绝对评分开销 ~8 s/恢复点）。

## G7 block-wise HVP 对照（完成，两轮一致）

- 首轮（seq=512、hvp_batches=2，脚本默认）结果
  （`results/paper_runs/blockwise_hvp/gpt2-medium_seed42_blockwise_analysis.json`）：
  - Spearman(block vs global HVP) = **0.536**（规格目标 ≥0.95，未达）
  - Mask IoU@20% = 0.797、@40% = 0.705（目标 ≥0.90，未达）
  - 峰值显存：block 23.7 GB vs global 30.6 GB（省 6.9 GB ✓）
  - 耗时：block 32.5 s vs global 3.3 s（block 慢 ~10×，因逐层建图）
- 判定（按必须补充实验清单）：排序/一致性不足 → block-wise HVP 只能作为
  **工程近似**报告，不能声称与 global HVP 等价；论文正文已将其表述为
  近似（rank-bottleneck 动机），实验不支持更强主张。
- 复测完成（seq=128、hvp_batches=8，`results/paper_runs/blockwise_hvp_seq128/...json`）：
  - Spearman = **0.514**、IoU@20% = 0.796、@40% = 0.701（两轮一致，均未达 0.95/0.90 目标）
  - 峰值显存：block 7.9 GB vs global 11.7 GB（省 3.8 GB）
  - 耗时：block 31.5 s vs global 3.7 s
- **最终判定**：G7"排序一致性 ≥0.95 / IoU ≥0.90"不成立。按清单判定规则，
  block-wise HVP 只能作为**工程近似 + 局限性说明**：省显存为真（约 1/3），
  但与 global HVP 排序相关性弱、时间更慢。
  值得注意：质量主结果使用的是 block-wise HVP 本身——其价值由最终任务质量
  （main_k3_signed 全胜）支撑，而非与 global HVP 的一致性；两者不矛盾：
  block 近似虽与 global 不同，但作为打分信号在恢复协议下更有效。
